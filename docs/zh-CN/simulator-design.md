# 调度模拟器设计

[English](../en/simulator-design.md) | **中文**

草案待审 · 2026-10-22

## 1. 目的

在写任何网络代码之前，用离散事件模拟验证调度机制本身：定窗取量、收尾缩量、超时回收、EWMA 估值、迟滞，是否真的能把汇总等待压到一个 W 以内，并调出 W、α、k、N 的合理值。

模拟器**不做**真实计算、真实网络、IR 翻译。节点是带噪声的数学模型，U 是带成本的记录。

## 2. 验证标准

跑完一个场景，以下四条全部满足才算调度机制成立：

| 编号 | 指标 | 通过线 |
| --- | --- | --- |
| V1 | 稳态下各轮时长（交回 − 发出）的极差，不含慢启动和收尾轮 | ≤ 0.2 × W |
| V2 | 每个批次的尾部等待（最早完成的节点空等到批次结束的时间） | ≤ 1 × W |
| V3 | 节点在门槛附近的升降档次数（开迟滞 vs 关迟滞） | 开迟滞后下降 ≥ 80% |
| V4 | 掉线节点的 U 被回收重发后，批次完成时间的额外延迟 | ≤ 2 × W + 该节点一轮取量 ÷ 剩余总吞吐 |

另外输出但不设通过线：调度端消息数 / 秒、各节点空闲率、重发 U 占比。

## 3. 模型

### 3.1 节点

每个节点由以下参数生成，全部可在场景文件里配置：

| 参数 | 含义 | 噪声模型 |
| --- | --- | --- |
| r_true | 真实计算吞吐（U/s） | 每轮乘以对数正态噪声，σ 可配（模拟降频、后台负载） |
| B_true | 真实带宽（字节/s） | 同上 |
| c | 并发度 | 固定 |
| online | 在线 / 离线 | 两状态马尔可夫链，平均在线时长和平均离线时长可配 |
| hardware_tier | 通用 / GPU 通用 | 固定 |
| latency | 单次往返固定开销（s） | 固定，加到每轮的传输时间上 |

节点执行一轮 n 个 U 的真实耗时 = latency + 数据量 ÷ B_true + n ÷ (r_true × 本轮噪声)。节点**不知道**自己的 r_true，调度端也不知道，只能从交回时刻反推——这是模拟的核心：估值和真值之间的差距由机制吸收。

### 3.2 工作负载

| 参数 | 含义 |
| --- | --- |
| E 数量、每个 E 的 U 数 | 批次规模 |
| 依赖形态 | parallel（全并行）/ serial（全串行）/ fanout-reduce（N 个并行 + 1 个归约 U）/ 自定义 DAG |
| U 成本 | 计算成本（相对单位）和输入大小（字节），可均一或按分布随机 |
| 目标 ET | 按耗时上限和硬件档 |
| 到达模式 | 一次性全部提交 / 按泊松到达 |

### 3.3 调度端

严格按设计文档第 7–9 节实现：

- 节点表：每节点维护 r、σ、B 的 EWMA 估值，consecutive_pass，in_flight。
- ET：键 = (硬件档, t_max)，就绪队列 FIFO。
- 取量：r_保守 × W，至少 c；批次剩余不足一轮时按比例缩量。
- 下道规则：节点先查最快有资格的 ET。
- 超时：issued_at + k × W 未交回则回收重发。
- 迟滞：升档要求 t ≤ t_max × (1 − band) 且连续 N 轮达标，降档一轮 t > t_max 即降。
- 依赖解析器：U 完成 → 检查下游 → 入 ET。

调度端的每个决策都只用它能观测到的量（交回时刻、数据量），不读节点的真值。代码上用类型把两者隔开，防止模拟器"作弊"。

## 4. 离散事件引擎

单线程，事件按时间戳排序的优先队列（`BinaryHeap`）。事件类型：

| 事件 | 触发 | 处理 |
| --- | --- | --- |
| NodePull | 节点空闲且在线 | 调度端按取量规则发放一轮；若无 U 可发，节点在 W/4 后重试 |
| RoundDone | 一轮的真实耗时到期 | 更新估值；解析器解锁下游；节点立即 NodePull |
| NodeOffline / NodeOnline | 马尔可夫链 | 离线时在途 U 不会交回（等超时回收）；上线后 NodePull |
| TimeoutCheck | 每 W/4 一次 | 扫描 in_flight，超时的 U 放回 ET |
| EventArrival | 按到达模式 | 编译 E，入解析器 |

随机数用固定种子，同一场景可重现。

## 5. 输出

- `results/<场景名>/rounds.csv`：每轮一行，节点、发出时刻、交回时刻、取量、估值 r、真值 r。
- `results/<场景名>/batches.csv`：每批次一行，开始、结束、尾部等待、重发数。
- `results/<场景名>/summary.txt`：V1–V4 的数值和通过 / 不通过。
- 参数扫描模式：对 W、α、k、N 各取一组值做网格，输出每组的 V1–V4，用来选默认值。

## 6. 场景

初始四个场景，对应四条验证标准：

| 场景 | 配置要点 | 主要看 |
| --- | --- | --- |
| basic | 2 快 + 2 慢节点，无噪声，无掉线，全并行 E | V1、V2：机制在理想条件下是否成立 |
| noisy | 同上 + σ = 0.3 的吞吐噪声 | V1、V2 在噪声下的退化程度；扫描 k |
| flapping | 一个节点的 r_true 恰在快 ET 门槛附近来回 | V3；扫描 N |
| churn | 8 节点，平均在线 10 分钟 / 离线 2 分钟 | V4；扫描超时倍数 |

后续可加：fanout-reduce 依赖、泊松到达、两个硬件档。

## 7. 代码结构（Rust）

```
sim/
  Cargo.toml
  src/
    main.rs        命令行：sim run <scenario.toml> / sim sweep <sweep.toml>
    engine.rs      事件队列与时钟
    node.rs        节点真值模型（噪声、在线状态）
    scheduler/
      mod.rs       节点表、ET、取量、超时、迟滞
      resolver.rs  依赖解析
      estimate.rs  EWMA、σ、r_保守
    workload.rs    E / U 生成与依赖形态
    metrics.rs     V1–V4 计算与 CSV 输出
    scenario.rs    TOML 配置解析
  scenarios/
    basic.toml  noisy.toml  flapping.toml  churn.toml
```

依赖只用 `serde` + `toml`（配置）、`rand` + `rand_distr`（噪声）、`csv`（输出）。不引入异步运行时，单线程足够。

`scheduler/` 这一层按设计文档的接口写，目标是后续原型直接复用：把 `engine.rs` 换成真实网络和时钟，调度逻辑不改。
